# KeyShift — カラオケ練習プレイヤー

端末内の音楽ファイルを読み込み、**テンポを変えずにキーだけ**（あるいはキーを変えずにテンポだけ）を変えて再生できる、歌の練習に特化した個人用プレイヤーです。

音源の取得機能はありません。ファイルはサーバーへ送信されず、すべてブラウザ内で処理・保存されます。

---

## 使い方

```bash
npm install
npm run dev      # http://localhost:3000
```

本番ビルド（静的書き出し）:

```bash
npm run build    # out/ に静的ファイルが出力される
npx serve out
```

`out/` はそのままどこにでも置けます。1度開けば Service Worker により**通信なしでも起動**します。

サブディレクトリ配信（GitHub Pages など）の場合は、基準パスをビルド時に渡します:

```bash
NEXT_PUBLIC_BASE_PATH=/snappdf/keyshift npm run build
```

このリポジトリでは `main` への push で GitHub Actions が SnapPDF と一緒にビルドし、
`https://<ユーザー名>.github.io/snappdf/keyshift/` へ配信します。

テスト:

```bash
npm test         # 型チェック + 再生エンジンのDSPテスト
```

## 機能

### 楽曲

- MP3 / WAV / M4A / AAC / FLAC（ブラウザがデコードできる形式なら OGG・Opus も可）
- ウィンドウへのドラッグ＆ドロップ、またはファイル選択で追加
- ID3v2・MP4(ilst)・FLAC(Vorbis Comment)・WAV(LIST-INFO) から曲名 / アーティスト / アルバム / アルバム画像を読み取り
- タグがなければファイル名から「アーティスト - タイトル」を推測
- 曲名・アーティスト・アルバム・ファイル名・メモを対象にした検索（全角/半角・大小文字を吸収）
- 追加順 / タイトル / アーティスト / 再生回数 / 再生時間で並び替え

### キーとテンポ

| | 範囲 | 挙動 |
|---|---|---|
| キー | −12 〜 +12 半音 | テンポは変わらない |
| テンポ | 0.50 〜 2.00 倍 | キーは変わらない |

どちらも再生を止めずにリアルタイムで反映されます。

### 再生

再生 / 一時停止 / 停止 / シークバー / 次へ / 前へ / 音量 / シャッフル / リピート（オフ・全曲・1曲）

### 練習向け

- **ABリピート** — A地点とB地点を指定して区間だけ繰り返し
- **波形表示** — クリック／ドラッグでシーク、A・B地点とリピート区間を可視化
- **歌いやすいキーのメモ** — 曲ごとに自由記述（例:「この曲は -3 が歌いやすい」）。一覧にバッジが出て検索対象にもなる
- **スリープタイマー** — 15 / 30 / 45 / 60 分で自動停止
- お気に入り、最近再生した曲、プレイリスト（作成・追加・削除・ドラッグで並び替え）

### 曲ごとの設定保存

キー・テンポ・音量・A/B地点・お気に入り・メモ・再生回数を曲ごとに保存します。次に開いたときは前回選んでいた曲が設定込みで復元されます（自動再生はしません）。

### ショートカットキー

| キー | 動作 |
|---|---|
| `Space` | 再生 / 一時停止 |
| `←` `→` | 5秒 戻る / 進む |
| `Shift + ←` `→` | 前の曲 / 次の曲 |
| `↑` `↓` | 音量 |
| `Z` `X` | キー −1 / +1 半音 |
| `C` `V` | テンポ −0.05 / +0.05 倍 |
| `0` | キーとテンポを原曲に戻す |
| `A` `B` | A地点 / B地点を指定 |
| `L` | ABリピート ON / OFF |
| `S` `R` `M` `F` | シャッフル / リピート / ミュート / お気に入り |
| `/` | 検索欄へフォーカス |
| `?` | ショートカット一覧 |

文字入力中は無効になります。

## 音質について

キー変更は `public/worklets/keyshift-processor.js` の AudioWorklet で行っています。デコード済みPCMを Worklet 自身が保持して音源になる構成なので、シーク・ABリピート・キー/テンポ変更がサンプル単位で正確に、再生を止めずに行えます。

```
PCM ─► WSOLA タイムストレッチ (alpha) ─► アンチエイリアスLPF ─► 3次補間リサンプル (rho)

  ピッチ比   P     = 2^(半音/12)
  テンポ比   T     = 再生速度
  リサンプル rho   = P          … 速度も音程も P 倍になる
  ストレッチ alpha = P / T      … 速度だけ元に戻し、音程変化だけを残す
```

- **WSOLA**（波形類似オーバーラップ加算）で伸縮するため、位相ボコーダ特有の「金属的な響き」が出にくく、歌声の質感が保たれます。オーバーラップ位置は正規化相互相関で探索し、粗探索（4サンプル刻み）＋近傍の精探索で負荷を抑えています。
- **キーを上げるときはアンチエイリアス用の4次バターワースLPF**を通してから間引くため、折り返しノイズが乗りません。
- **キー ±0・テンポ 1.00 倍のときは無加工**です。波形類似探索をスキップし、補間係数も 0 になるため、入力サンプルがそのまま出力されます（`npm test` で誤差 6e-8 = float32 の丸め誤差以下であることを検証しています）。

`npm test` は正弦波を流して、8通りのキー／テンポの組み合わせで出力周波数が理論値と ±1セント以内に収まること、長さが理論値どおりになること、ABリピート・終端検出・一時停止・長時間再生の安定性を確認します。

## パフォーマンス

- 曲リストは仮想スクロール。3000曲でもDOMは25行程度しか作らず、表示 0.6秒 / 検索 60ms / ビュー切替 140ms / JSヒープ 9MB 程度で動きます。
- デコード済みPCMは Worklet へ**所有権ごと転送**するため、メインスレッドに残りません。60回の曲切り替えと240回のパラメータ操作でヒープが増えないことを確認しています。
- 次の曲は再生開始の1.5秒後にバックグラウンドで先読みします（20分を超える曲は先読みしません）。
- 波形のピークデータは IndexedDB にキャッシュし、2回目以降はデコードを待たずに表示します。

## データの保存場所

| 内容 | 保存先 |
|---|---|
| 音楽ファイル本体 / アルバム画像 / 曲メタデータ / 曲ごとの設定 / プレイリスト / 波形キャッシュ | IndexedDB（`keyshift`） |
| テーマ（ダーク/ライト）、前回開いていた曲 | localStorage |

外部への通信は一切行いません。フォントやアイコンも含めて外部CDNを使っていないため、オフラインでも見た目が変わりません。

ブラウザのサイト データを削除すると、登録した曲もまとめて消えます。元のファイルは各自で保管してください。

## 技術構成

TypeScript / React 19 / Next.js 16（App Router・静的書き出し）/ Tailwind CSS v4 / Web Audio API（AudioWorklet）

実行時の依存は React と Next.js のみで、タグ解析・波形描画・時間伸縮・仮想スクロールはすべて自前実装です。
